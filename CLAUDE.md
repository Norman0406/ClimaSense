# ClimaSense

ESP32-based indoor environment sensor. Measures ambient data periodically and publishes it via MQTT to a broker. Wi-Fi credentials are configured through a captive portal served by the device.

The repository contains both the **hardware** (KiCad PCB) and the **firmware**.

## Language

- Everything in this repository is written in **English**: code, comments, commit messages, docs, schematic labels.
- Reply to the user in English, even if they write in German.

## Hardware ground rules

- EDA tool: **KiCad** (all design files live in `hardware/`, versioned as text).
- The board is **fully manufactured and assembled by a fab** (PCBA, e.g. JLCPCB / PCBWay). The user does not hand-solder.
  - Prefer parts that are stocked by the assembler's parts library (LCSC for JLCPCB). Record the LCSC / manufacturer part number for every BOM line.
  - SMD only where possible; avoid parts that need manual or through-hole assembly unless the fab offers it.
  - Keep fab outputs (Gerbers, BOM, CPL/position files) reproducible from the KiCad project.
- Power: **USB-C** first. Battery operation with charging is a possible later revision — don't block it in the layout, don't build it yet unless decided.
- Temperature/humidity accuracy matters: keep T/RH sensors thermally isolated from the ESP32, regulator and other heat sources (board edge, milled slots, no copper pour under them).

## Revision 1.0 configuration (decided — see `docs/decisions.md`)

- MCU: **ESP32-C6-WROOM-1-N8** (chosen for now; ESP32-C5 with 5 GHz was preferred but not sourceable at the fab).
- Sensors on I2C (IO6/IO7, nothing else on that bus): **SHT45** (T/RH), **SCD41** (CO2), **SGP41** (VOC/NOx), **BMP580** (pressure).
- Extras: RGB status LED, Qwiic connector on its own I2C bus (IO19/IO20) with its own switchable supply (`QWIIC_EN`, off by default), two buttons (combined BOOT/user, and RESET). No test pads and no pogo/Tag-Connect footprint (both were considered and dropped).
- Programming: native USB of the C6 through the USB-C port, OTA when deployed. No USB-UART bridge; UART0 (IO16/IO17) is not brought out.
- Not in revision 1.0: ambient light sensor and microphone (deferred idea: detect piano playing outside quiet hours, log daylight), battery operation.
- The BME680 used on the breadboard prototypes is dropped.
- Quantity: at least 5 boards, assembled at JLCPCB.

## Working on the schematic

- KiCad 10 is installed at `C:\Program Files\KiCad\10.0` (`bin\kicad-cli.exe` for rule checks, netlist and PDF export).
- `python hardware/tools/check_schematic.py` — runs ERC, compares KiCad's netlist with the intended one, plots `hardware/build/climasense.pdf`. Run it after any schematic change.
- `python hardware/tools/gen_schematic.py` — regenerates and **overwrites** `hardware/climasense.kicad_sch`. Only use it while the schematic has not been edited by hand in KiCad; check `git log`/diff first. After layout starts, the `.kicad_sch` is the source of truth.
- Pin map, BOM with JLCPCB numbers and open layout points: `docs/hardware/schematic.md`.
- Project footprints (ESP32-C6-WROOM-1, SGP41, BMP580, RGB LED) are in `hardware/lib/climasense.pretty`, generated by `python hardware/tools/gen_footprints.py` with each dimension referenced to its datasheet drawing; notes in `docs/hardware/footprints.md`. Change dimensions in the script, not in the `.kicad_mod` files. They are unproven on a real board.
- `check_schematic.py` also verifies that every part has a footprint and every symbol pin a same-numbered pad.

## Working on the PCB

- `hardware/climasense.kicad_pcb` is created by `hardware/tools/gen_pcb.py`, which needs KiCad's own Python: `"C:\Program Files\KiCad\10.0\bin\python.exe" hardware/tools/gen_pcb.py`. It places the parts, routes the board (`route_board.py` on top of the grid router in `router.py`; about a minute, deterministic) and fills the pours. A few critical connections are drawn by hand in `PREROUTED` in `gen_pcb.py` (buck converter input loop, SCD41 supply link, ESP32 supply pin); change those there, on the 0.1 mm grid. It **overwrites** the board — never run it once the board has been edited by hand in KiCad. `--no-route` stops after placement; `--attempts=N` limits the routing retries.
- `python hardware/tools/check_pcb.py --require-routed` — KiCad DRC including board-versus-schematic comparison and open-connection count, plus a 3D render to `hardware/build/pcb_3d_top.png`. Run it after any board, placement or footprint change. Trust KiCad's count of open connections, not the router's own report: the two have disagreed before. The check has also caught a footprint error that visual review missed.
- Scripts that import `pcbnew` must call `wx.DisableAsserts()` first, otherwise KiCad debug alerts pop up as dialogs on the user's screen.
- The board hangs on a wall in landscape with the USB cable down; the sensor side is arranged so heat rises away from the SHT45. Keep that in mind for any placement change, and ask the user before changing placement.
- When passing a net name such as `/I2C_SDA` to a script from Git Bash, set `MSYS_NO_PATHCONV=1`, or the leading slash is rewritten into a Windows path.
- `"C:\Program Files\KiCad\10.0\bin\python.exe" hardware/tools/audit_pcb.py` — measures what DRC does not: track length against the shortest possible connection, widths, supply-path resistance, parallel runs, and tidiness (it fails if a net crosses itself or has a loop; it lists off-centre pad entries and right-angle corners). Run it after every re-route, and look at a KiCad plot of the result as well: several router defects were only found by looking.
- Board concept, zones, design rules, routing approach and the open review findings: `docs/hardware/layout.md`.
- `python hardware/tools/gen_fab.py` — writes the JLCPCB order files (Gerber archive, BOM, placement file) into `hardware/fab/` after running the board check. The placement file carries rotation and centre corrections for the parts JLCPCB draws differently from KiCad (`CORRECTIONS` in the script); they are measured, but only JLCPCB's placement preview confirms them. Ordering steps and the preview checklist: `docs/hardware/ordering.md`.
- The ESP32-C6 pulls IO18–IO23 high while it is in reset; IO10 and IO11 float. Check `docs/hardware/schematic.md` before moving a signal that must be low at power-up.

## Firmware ground rules

- Periodic measurement → publish via MQTT.
- Captive portal (SoftAP) for Wi-Fi provisioning.
- Framework: **ESP-IDF 6.1, in C++** (decided, see `docs/decisions.md`): no exceptions, no RTTI, no heap-allocating containers in the measurement path; vendor drivers stay C. Project in `firmware/`, built with `idf.py`; build and flash steps in `firmware/README.md`.
- Pin map in code: `firmware/main/board.h`. Keep it in step with `docs/hardware/schematic.md`.

## Decisions
